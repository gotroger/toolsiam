### ffmpeg core

- `scripts/copy-ffmpeg.mjs`: wasm 30.7 MB → `.wasm.gz` 9.8 MB (10,257,774 byte) idempotent รันซ้ำข้ามได้
- `wrangler dev` เสิร์ฟ `.wasm.gz` เป็น `application/gzip` ไม่มี `Content-Encoding` → worker คลายเอง; `astro dev` เสิร์ฟพร้อม `Content-Encoding: gzip` → เบราว์เซอร์คลายให้ worker ตรวจ magic bytes จึงทำงานทั้งสองแบบ
- `time` ใน progress ของ core เป็นไมโครวินาที (ตัด 3 วินาทีได้ค่า 3.0155)
- ไฟล์เสียหาย (ไบต์สุ่ม 50 KB) → "ไฟล์เสียหายหรือเป็นชนิดที่อ่านไม่ได้" และ core รับงานถัดไปได้ทันที
- `public/_headers` ตั้ง `/ffmpeg/*` เป็น `max-age=31536000, immutable` (เวอร์ชันอยู่ใน path) — กฎนี้ครอบ `manifest.json` ด้วย จึงให้ `engine.ts` fetch manifest แบบ `cache: "no-store"` เพื่อไม่ให้ผู้ใช้เก่าค้างเวอร์ชันเดิมหลังอัปเกรด (ลองกฎ `/ffmpeg/*/*` แล้ว wrangler ไม่ match)

ไฟล์ทดสอบเป็น testsrc ที่บีบอัดยาก คลิปจริงจะเล็กลงมากกว่านี้

- ยกเลิกกลางคัน (ลดขนาด): ระหว่างทำปุ่มหลักและ fieldset ถูกปิด มีปุ่มยกเลิกและแถบความคืบหน้า; หลังยกเลิกปุ่มกลับมา ไม่มีลิงก์ดาวน์โหลด สถานะ "ยกเลิกแล้ว ปรับค่าหรือลองใหม่ได้" และกดใหม่แล้วโหลด core จาก cache และทำจนเสร็จ
- เปลี่ยนค่า (บิตเรต) หลังได้ผลลัพธ์ → ผลลัพธ์และ object URL ถูกล้าง
- ตรวจค่าก่อนเริ่ม: ไม่มีไฟล์, นามสกุลผิด, เวลาเริ่ม ≥ จบ, เวลาจบเกินความยาวคลิป (0:12), GIF > 15 วิ — ทั้งหมดแสดง error และย้ายโฟกัส ไม่แตะ engine

## แก้ระหว่าง QA

1. **ตัดคลิปเร็วได้ 12 วิแทน 7 วิ** — `-avoid_negative_ts make_zero` เลื่อนเฟรมตั้งแต่คีย์เฟรมก่อนจุดเริ่มมาเป็นเวลา 0 ทำให้ `-t` ครอบทั้งคลิป ตัดออกแล้วให้ muxer เขียน edit list แทน (ทดสอบ CLI: 7.00 วิ ทั้งไฟล์คีย์เฟรมห่าง 8 วิ และ 2 วิ)
2. **webm ตัดแบบเร็วได้ 6 วิแทน 4 วิ** — WebM ไม่มี edit list จึงบังคับใช้โหมดแม่นยำ (เข้ารหัสใหม่เป็น MP4) สำหรับ webm เสมอ
3. **รูปปก YouTube ขนาดที่ไม่มีจริงบางคลิปไม่ 404** แต่ส่งรูปแทน 120×90 กลับมา (`jNQXAC9IVRw`) → ซ่อนเมื่อ `naturalWidth` น้อยกว่าครึ่งของขนาดที่คาด (ตรวจซ้ำหลังแก้: คลิปเก่าเหลือ 2 ขนาด คลิป HD ยังครบ 4)
4. **กฎ `_headers` `/ffmpeg/*` ครอบ `manifest.json`** และ `/ffmpeg/*/*` ไม่ match ใน wrangler → คงกฎ `/ffmpeg/*` แต่ fetch manifest ด้วย `cache: "no-store"` (ตรวจด้วย curl หลัง restart wrangler: ทุกไฟล์ใต้ /ffmpeg/ เป็น immutable)

## ยังไม่ได้ทดสอบ

- **iPhone Safari จริง** กับไฟล์ใกล้ 100 MB — สเปกข้อ 3 กำหนดให้ยืนยันก่อนปล่อย ถ้าแท็บถูกฆ่าให้ลดขีดจำกัดเป็น 60 MB
- offline หลัง core อยู่ใน cache — เครื่องมือทดสอบตัดเครือข่ายไม่ได้ในรอบนี้; ด้วย `_headers` ใหม่ core จะถูก cache แบบ immutable จึงคาดว่าใช้ได้ แต่ยังไม่ได้พิสูจน์
- ไฟล์ HEVC (.mov จาก iPhone ที่ตั้งค่า High Efficiency) — core มี decoder HEVC แต่ยังไม่ได้ลองไฟล์จริง
- คลิปที่เบราว์เซอร์แสดงตัวอย่างไม่ได้ (เส้นทาง "ไม่มีเปอร์เซ็นต์ความคืบหน้า")
