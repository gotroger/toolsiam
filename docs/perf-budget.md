# Performance Budget

ตัวเลขในไฟล์นี้ **วัดจากของจริง ไม่ได้ตั้งเอาไว้ล่วงหน้า** (§21.2) — เดาตัวเลขแล้วจะได้ gate ที่หลวมจนไร้ประโยชน์
หรือแน่นจนบล็อกงานโดยไม่มีเหตุผล

```bash
npm run size          # วัดแล้วเทียบกับ budget ด้านล่าง — เกิน = exit 1
npm run size -- --json  # ผลดิบ ใช้ตอนตั้ง baseline ใหม่
```

`npm run size` นับ "JS ของหน้า" เป็นไฟล์ที่เบราว์เซอร์ต้องโหลดจริงจนหน้าทำงานครบ: script ที่อ้างจาก HTML
บวก static import ที่ตามไปจนสุด บวก chunk ของเครื่องมือที่ `ToolIsland` โหลดแบบ dynamic
(อ่านจากตาราง `__vite__mapDeps` ที่ Vite ใส่ไว้ จึงตรงกับสิ่งที่โหลดจริง ไม่ใช่การประมาณ)

## Budget ปัจจุบัน

`budget = max(baseline_p95 × 1.15, หน้าที่หนักที่สุดในกลุ่ม × 1.05)` · หน่วยเป็น byte หลัง gzip

**ทำไมต้องมีพื้นล่างจากหน้าที่หนักที่สุด (เพิ่มที่ Phase 3):** `npm run size` ใช้ budget ของกลุ่ม
เป็นเพดานของ **หน้ารายหน้า** ด้วย ถ้าตั้งจาก p95 อย่างเดียว การเพิ่มหน้าเบา ๆ จำนวนมาก
จะดึง p95 ลงจน budget ต่ำกว่าหน้าที่หนักที่สุดที่มีอยู่แล้ว แล้ว fail ทันทีทั้งที่ไม่มีอะไรแย่ลง
— เจอจริงตอนจบ Phase 3 ที่ `/tools` (103.8 KB) จะเกิน budget ที่คำนวณจาก p95 ใหม่ (86.6 KB)

```json
{
  "measuredAt": "2026-09-09",
  "basis": "JS = max(p95 × 1.15, หน้าหนักสุด × 1.05) · HTML/CSS = p95 × 1.15 (Tool discovery refactor)",
  "limits": {
    "cssGzip": 13825,
    "toolPageJsP95": 129273,
    "toolPageHtmlP95": 13894,
    "contentPageJsP95": 115962,
    "contentPageHtmlP95": 15026
  }
}
```

`npm run size` ตรวจสองชั้น: ค่า p95 ของแต่ละกลุ่ม และ **หน้ารายหน้า** — หน้าเดียวที่โดดขึ้นมาเกิน budget
ของกลุ่มตัวเองก็ fail แม้ p95 จะยังผ่าน

## กติกาการแก้ budget

1. **เกิน budget = fail** — แก้ให้เล็กลงก่อนเป็นทางเลือกแรกเสมอ
2. **ยกระดับ budget ได้** ถ้าการเพิ่มขึ้นมีเหตุผลที่อธิบายได้ โดยต้องบันทึกลงตารางด้านล่าง
   พร้อมชื่อ Phase เหตุผล และตัวเลขใหม่ — ห้ามแก้ตัวเลขเงียบ ๆ
3. **ทบทวน baseline ทุกครั้งที่จบ Phase** — วัดใหม่ ตั้ง budget ใหม่จาก baseline ที่วัดได้
4. ห้ามเพิ่ม production dependency หรือ devDependency เพื่อแก้ปัญหาขนาด (PF2 / E8)

## Tool discovery refactor — 2026-09-09

วัด build เดิมจาก git HEAD และ build ใหม่ด้วย dependency ชุดเดียวกัน: CSS เพิ่มจาก 8.7 KB เป็น 11.8 KB gzip จาก product tokens, responsive bento, search overlay และ motion ที่รองรับ reduced motion; หน้า `/tools` ลด JS จาก 107.9 KB เหลือประมาณ 77.4 KB เพราะ island รับเฉพาะข้อมูล discovery โดยไม่ import registry พร้อม FAQ/แหล่งอ้างอิงทั้งชุดเข้า browser bundle.

หน้าแรกเพิ่ม JS จาก 63.4 KB เป็นประมาณ 81.2 KB เพื่อค้นหาแบบทันที โดยแชร์ React ที่ใช้กับผลหวยเดิม; HTML หน้าแรกเพิ่มจาก 10.1 KB เป็นประมาณ 14.9 KB และ HTML p95 ของหน้าเนื้อหาเพิ่มเป็นประมาณ 12.7 KB เพราะฝังข้อมูล discovery ให้หน้าแรกและหมวดหมู่ค้นหาได้ทันทีโดยไม่รอ request. ถอดภาพปก 16:9 ออกจาก tool tiles และใช้ SVG/CSS แทน ไม่มี dependency เพิ่ม.

ปรับเฉพาะเพดาน CSS และ content HTML ตามค่าที่วัด × 1.15; JS และ tool HTML ใช้เพดานเดิม. การเพิ่มขนาดเป็นต้นทุนของ search และ design system ใหม่ตาม brief ไม่ใช่การอ้างว่าค่า Core Web Vitals ภาคสนามดีขึ้น.
