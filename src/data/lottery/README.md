# ข้อมูลผลสลากกินแบ่งรัฐบาล

โฟลเดอร์นี้เก็บผลรางวัลรายงวดเป็นไฟล์ JSON ไฟล์ละหนึ่งงวด ชื่อไฟล์คือวันที่ออกรางวัลในรูป `YYYY-MM-DD.json`

**ตอนนี้ยังไม่มีไฟล์งวดใด ๆ** — หน้า `/lottery` ทั้งหมดจึงยังไม่ถูก build และไม่ขึ้น production
(หลักเดียวกับหมวด `planned` ใน §8.4 คือหน้าเปล่าไม่ควรให้ผู้ใช้และ crawler เจอ)
วันที่วางไฟล์งวดแรกลงที่นี่ หน้าทั้งหมดจะปรากฏพร้อมกันเองโดยไม่ต้องแก้โค้ด

## ทำไมข้อมูลถึงต้องกรอกด้วยคน

ผลรางวัลเป็นข้อเท็จจริงที่คนเอาไปใช้ตรวจว่าตัวเองถูกรางวัลหรือไม่ ข้อมูลผิดหนึ่งหลักมีผลจริงกับคนอ่าน
แหล่งทางการมีแหล่งเดียวคือสำนักงานสลากกินแบ่งรัฐบาล (glo.or.th) และ endpoint ที่หน้าเว็บเขาใช้
ไม่ใช่ public API ที่ประกาศ จึงไม่มีการรับประกันความเสถียร (§28.2)

กระบวนการกรอกมือจึงเป็น **กระบวนการจริงของ production ไม่ใช่ของชั่วคราว** ใช้เวลาราว 5 นาทีต่องวด
และมีปีละ 24 งวด

## ขั้นตอนเพิ่มงวดใหม่

1. เปิดประกาศผลรางวัลของงวดนั้นจาก glo.or.th
2. สร้างไฟล์ `src/data/lottery/<YYYY-MM-DD>.json` ตามรูปแบบด้านล่าง
3. รัน `npm test` — validator จะตรวจจำนวนหลัก จำนวนรางวัลต่อประเภท เลขซ้ำ
   และตรวจว่ารางวัลข้างเคียงตรงกับรางวัลที่ 1 จริง
4. **ตรวจซ้ำด้วยสายตาอีกสองรอบเทียบกับประกาศ** — validator ตรวจได้แค่รูปร่าง
   ตรวจไม่ได้ว่าเลขที่กรอกตรงกับประกาศหรือไม่
5. เมื่อตรวจซ้ำแล้วให้เปลี่ยน `status` เป็น `"verified"` (ก่อนหน้านั้นใช้ `"validated"`
   ซึ่งหน้าเว็บจะขึ้นป้าย "รอการตรวจสอบซ้ำ" ให้ผู้ใช้เห็น)
6. commit แล้ว deploy
7. เมื่อมีข้อมูลงวดแรกแล้ว ให้เปลี่ยนหมวด `lottery` ใน `src/tools/categories.ts`
   จาก `status: 'planned'` เป็น `'active'` เพื่อให้ขึ้นหน้าแรกและ footer

## รูปแบบไฟล์

```json
{
  "drawDate": "2026-09-01",
  "prizes": {
    "first": ["123456"],
    "firstNear": ["123455", "123457"],
    "second": ["......", "......", "......", "......", "......"],
    "third": ["...... × 10 รายการ"],
    "fourth": ["...... × 50 รายการ"],
    "fifth": ["...... × 100 รายการ"],
    "threeDigitFront": ["111", "222"],
    "threeDigitBack": ["333", "444"],
    "twoDigitBack": ["55"]
  },
  "sourceUrl": "https://www.glo.or.th/...",
  "enteredAt": "2026-09-02",
  "status": "validated"
}
```

**ทุกหมายเลขต้องเป็นสตริง** ห้ามเป็นตัวเลข เพราะเลขศูนย์นำหน้าคือส่วนหนึ่งของหมายเลข
`"012345"` ไม่เท่ากับ `12345` — validator จับกรณีนี้ให้ แต่ให้ระวังตั้งแต่ตอนกรอก
