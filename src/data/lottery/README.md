# ข้อมูลผลสลากกินแบ่งรัฐบาล

โฟลเดอร์นี้เก็บผลรางวัลรายงวดเป็นไฟล์ JSON ไฟล์ละหนึ่งงวด ชื่อไฟล์คือวันที่ออกรางวัลในรูป `YYYY-MM-DD.json`

ข้อมูลดึงจาก API ของสำนักงานสลากกินแบ่งรัฐบาลด้วย `npm run lottery`

## เพิ่มงวดใหม่

```bash
npm run lottery              # ดึงงวดที่ยังไม่มีไฟล์ ย้อนหลังสูงสุด 24 งวด
npm run lottery -- --all     # ดึงทุกงวดที่ API มี (ปัจจุบัน 100 งวด)
npm run lottery -- --limit=4 # จำกัดจำนวนงวด
npm run lottery -- --force   # ดึงทับไฟล์เดิม
npm test                     # validator ตรวจไฟล์ทั้งหมด
```

สคริปต์ข้ามงวดที่มีไฟล์อยู่แล้ว จึงรันซ้ำได้ทุกเมื่อหลังออกรางวัล (วันที่ 1 และ 16 ของเดือน)

## endpoint ที่ใช้

| endpoint | body | ได้อะไร |
|---|---|---|
| `POST /api/lottery/getPeriodList` | — | รายการวันที่ทุกงวด |
| `POST /api/checking/getLotteryResult` | `{"date":"01","month":"09","year":"2026"}` | ผลครบทุกรางวัลของงวดนั้น |

⚠️ **ทั้งสองไม่ใช่ public API ที่ประกาศ** เป็น endpoint ที่หน้าเว็บของสำนักงานสลากฯ เรียกใช้เอง
จึงไม่มีการรับประกันความเสถียรหรือรูปแบบข้อมูล (§28.2) สคริปต์จึงตรวจทุกอย่างที่ตรวจได้ก่อนเขียนไฟล์
— จำนวนรางวัลต่อประเภท ชนิดข้อมูล และวันที่ที่ API คืนต้องตรงกับที่ขอ — และหยุดงวดนั้นทันทีเมื่อไม่ตรง
แทนที่จะเขียนข้อมูลครึ่ง ๆ กลาง ๆ ลงไป

ถ้าวันหนึ่ง endpoint เปลี่ยนหรือหายไป ยังกรอกไฟล์ JSON เองได้ตามรูปแบบด้านล่าง
โครงสร้างไฟล์ไม่ผูกกับ API

## ทำไม status ยังเป็น validated

ข้อมูลมาจาก API ทางการโดยตรงจึงไม่มีความผิดพลาดจากการพิมพ์ แต่ยังไม่มีคนเปิดประกาศเทียบด้วยตา
ตาม §28.3 จึงยังเป็น `validated` และหน้าเว็บขึ้นป้าย "รอการตรวจสอบซ้ำ" ให้ผู้ใช้เห็น
เมื่อตรวจซ้ำกับประกาศแล้วจึงเปลี่ยนเป็น `verified` เอง

## ถ้ายังไม่มีไฟล์งวดใดเลย

หน้า `/lottery` ทั้งหมดจะไม่ถูก build และไม่ขึ้น production (gate ด้วย `HAS_DRAWS`)
ตามหลักเดียวกับหมวด `planned` ใน §8.4 คือหน้าเปล่าไม่ควรให้ผู้ใช้และ crawler เจอ

## รูปแบบไฟล์

```json
{
  "drawDate": "2026-09-01",
  "prizes": {
    "first": ["123456"],
    "firstNear": ["123455", "123457"],
    "second": ["......", "......", "......", "......", "......"],
    "third": ["...... × 10 รายการ"],
    "fourth": ["...... × 50 รายการ"],
    "fifth": ["...... × 100 รายการ"],
    "threeDigitFront": ["111", "222"],
    "threeDigitBack": ["333", "444"],
    "twoDigitBack": ["55"]
  },
  "sourceUrl": "https://www.glo.or.th/...",
  "enteredAt": "2026-09-02",
  "status": "validated"
}
```

**ทุกหมายเลขต้องเป็นสตริง** ห้ามเป็นตัวเลข เพราะเลขศูนย์นำหน้าคือส่วนหนึ่งของหมายเลข
`"012345"` ไม่เท่ากับ `12345` — validator จับกรณีนี้ให้ แต่ให้ระวังตั้งแต่ตอนกรอก

## สิ่งที่ห้ามมีในเว็บนี้ (§9.2)

ระบบทำนายเลข · การแนะนำเลขเด็ด · สถิติ "เลขออกบ่อย" ที่สื่อเป็นคำแนะนำให้ซื้อ

### แก้สถานะจากการ audit 9 กันยายน 2569

สคริปต์เดิมตั้ง `verified` อัตโนมัติเมื่อดึงข้อมูล จึงเปลี่ยนงวดที่เก็บไว้ 27 งวดกลับเป็น `validated` เพราะยังไม่มีบันทึกการตรวจประกาศด้วยคนรายงวด; ผลรางวัลทั้ง 27 งวดตรวจเทียบ GLO API แล้วตรงกันตาม `output/playwright/audit-2026-09-09/lottery-verification.json` โดยการเปรียบเทียบ API ไม่ทดแทนการตรวจด้วยคนตามนิยาม `verified` และไม่ได้เปลี่ยนเลขรางวัล
